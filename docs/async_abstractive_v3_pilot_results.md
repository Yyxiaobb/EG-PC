# V3 异步摘要证据图：三数据集小样本对比

V3 首轮使用原始提示；每轮答案返回后，后台只摘要该轮原始证据并写入会话证据图；后续请求把当前原始证据与已完成的来源摘要一起检索。摘要仍在运行时，不等待它，也不使用尚未压缩完成的旧原文。摘要节点以原始证据句 ID 元数据保留出处映射，并建立实体关联。

## 实验设置

- 数据：HotpotQA、2WikiMultiHopQA、MuSiQue，各抽取 1%目标规模；实际每个数据集 1 个三轮会话，共 9 个问题。
- 答题模型：Qwen2.5-7B-Instruct Q4_K_M；生成不设固定 token 上限（EOS 或上下文边界停止）。
- V3 摘要模型：本地 Qwen2.5-0.5B-Instruct，CPU 推理，最多生成 64 tokens；相邻问题间隔 1 秒。
- 对比：无压缩、LLMLingua-2、V2 融合图、V3 异步摘要融合图。
- 完整请求延迟从压缩器调用到答案生成结束；答后摘要单独统计，不计入当前请求延迟。

## V3 异步记忆诊断

- 摘要在下一轮前完成：0/6（0%）。轮间隔 1 秒；CPU 摘要平均计算耗时 31.9 秒，平均含排队总完成时间 63.7 秒。
- 原始证据到摘要的平均 token 减少率 94.7%；回退到原文次数 0；后台错误数 0。
- 摘要图复用数均值 0.0/请求，压缩记忆命中数 0。没有摘要在下一轮前完成，所以本次 1 秒间隔试验没有检验到摘要图对后续回答质量的影响；V3 后两轮只融合当前材料与已就绪会话记忆（本次没有就绪摘要）。
- 本样本 V3 F1 0.1015、平均延迟 1319 ms；V2 F1 0.0984、平均延迟 1073 ms。每个数据集只有一个会话，差值不具统计解释力；V3 首轮使用原文也会增加 prefill。

实验验证了摘要在答复后运行且不阻塞当前请求，但 Qwen2.5-0.5B CPU 摘要无法在 1 秒间隙内服务下一问。小样本不能证明 V3 提高了回答质量。下一步应加速摘要并在真实会话间隔下验证摘要能及时落图且被下一问检索，再扩大样本。
