# V2 三数据集 3% 多轮实验协议

## 修改目的

旧策略允许历史分支仅凭较低的词面相关分数抢答，新需求可能因此丢失当前材料。V2 对新材料默认融合历史与当前检索结果；只有相同上下文已经缓存、历史检索覆盖全部当前来源时才允许历史捷径。来源覆盖只是保守条件，不是语义充分性的证明。

历史独有材料最多占可用证据预算的 20%，当前材料优先。使用 BM25、文本冗余惩罚和文档多样性选择证据，保留完整问题及回答标记。所有原始来源仍保留为溯源锚点，不能将该方法描述为“仅保存压缩材料”。

生成答案返回后，后台用真实 LLMLingua-2 压缩当前来源与通过筛选的历史来源的并集，包括未进入本轮回答提示的来源。每个压缩来源片段保留对应原文 ID。问题及未验证的生成答案单独压缩，不作为事实证据参与检索。禁止对旧压缩片段递归压缩。

## 数据与对照

- HotpotQA validation：222 / 7405 题，74 个会话。
- 2WikiMultihopQA validation：378 / 12576 题，126 个会话。
- MuSiQue dev：72 / 2417 题，24 个会话。
- 共 224 个三轮会话、672 个不同问题、五种方法合计 3360 次真实生成。

按 3% 目标向上取整，再向下保留完整三轮会话，因此 HotpotQA 与 MuSiQue 各少一题。会话按可见上下文标题和实体的关联构造，属于合成相关问答序列，不是自然用户多轮对话，也不是均匀随机的 QA 样本。检索与压缩决策不读取标准答案和 supporting facts。固定 seed=42，保存具体问题 ID 清单。

五种方法使用完全相同的问题与会话顺序：

1. 无压缩。
2. 旧双路会话证据图：保留旧抢答策略，但使用共同修正后的当前来源 ID 逻辑及共同预算；不是先前 10% 实验的逐项复刻。
3. 请求前 LLMLingua-2。
4. V2 融合会话证据图。
5. V2 融合会话证据图 + 生成后 LLMLingua-2。

方法 4 与 5 的消融用于观察后台压缩记忆的增量作用。方法 3 与 5 处在不同压缩层次，不能将它们的差异全部归因于 LLMLingua-2。

## 模型与预算

本地 Qwen2.5-7B-Instruct GGUF Q4_K_M，全部可卸载层使用 GPU，flash attention 开启，8192 token 上下文，最多生成 32 token。temperature=0、top_k=1、top_p=1，禁用请求 prompt cache；模型服务常驻。LLMLingua-2 使用本地 `llmlingua-2-bert-base-multilingual-cased-meetingbank`，GPU 运行，初始化与预热不计入单次延迟。

压缩方法使用相同的 50% **原生完整提示 token 上限**，实际输入 token 数单独报告；相同上限不代表实际长度相同。V2 与在线 LLMLingua-2 保留完整问题，固定指令与问题自身超过上限时允许必要开销并记录。LLMLingua-2 关闭整段筛选以保证输入与输出片段一一映射，保留其真实词元分类压缩，不用模拟压缩器。

## 状态与执行

每种方法、每个会话均新建证据图。不同会话、不同方法和不同实验之间不共享图状态。三个问题按会话顺序执行；相邻轮次配置 1000 ms 空窗，不因后台未完成而主动等待。后台实际可用时间还包括结果评估等少量客户端开销。

以会话为单位轮换五种方法的顺序。切换方法前排空上一方法后台工作，避免方法间 GPU 任务混杂；组合方法自身的后台与下一轮推理竞争保留在真实测量中。每完成一个三轮方法块落盘，汇总每个完整会话更新。后台来源映射或模型错误会使实验失败，不能静默混入结果。

断点续跑要求协议、问题清单、源代码 SHA256 完全一致，已完成块跳过，不复用历史图；未完成的会话方法块从空图重跑。

## 指标解释

质量报告答案 token F1、EM，按总体、数据集和轮次拆分。抽取式 evidence F1 仅作诊断，不能用它直接公平比较碎片化的 LLMLingua 输出与完整句子选择。

完整请求延迟从客户端开始压缩计时，到完整生成结果返回为止，包含分词、图检索、序列化、传输、服务排队与推理等请求路径开销，不包含模型初始化、结果评估和生成后任务。另列压缩墙钟、服务端 prefill/decode，以及旧式分项之和。不是首 token 延迟，也不是把用户思考时间算作请求延迟。

后台分别报告模型压缩调用耗时、队列等待、入图/其余处理、提交到入图总耗时。后台开销没有消失；若跨过空窗与下一轮竞争，其影响会反映在下一轮墙钟延迟中。就绪率在下一轮组合方法真正开始请求前检查，最终轮没有后续请求，排除在分母之外。短于平均空窗的平均后台时间不能替代逐轮就绪率。

同时报告历史证据复用、压缩来源片段实际入选、抢答分支及补充来源数量。如果压缩记忆很少被检索选用，即便质量或延迟改善，也不能宣称已经证明后台 LLMLingua-2 的收益。

## 复现

```powershell
python -m pytest -q
python scripts/run_real_7b_multiturn_v2.py --plan-only
python -u scripts/run_real_7b_multiturn_v2.py
# 仅在中断且代码及协议未变化时：
python -u scripts/run_real_7b_multiturn_v2.py --resume
```

默认结果前缀：`results/real_7b_multiturn_v2_3pct`。`_plan.json` 保存协议、清单、代码哈希；`.jsonl` 保存逐请求输出与压缩提示；`_summary.json` 保存增量汇总及完成标记。初始化失败、冒烟检查和未完成结果不能当作正式实验结论。
