# V2 三数据集约 3% 真实多轮实验结果

已完成 3360 次真实生成，224 个独立三轮会话、672 个不同问题。
使用本地 Qwen2.5-7B-Instruct Q4_K_M 和真实 LLMLingua-2；每种方法每个会话重新建图。

HotpotQA 222 / 7405，2Wiki 378 / 12576，MuSiQue 72 / 2417。采用标题/实体关联构造的合成三轮问答，不能等同自然多轮对话。

**结论：生成后 LLMLingua-2 记忆没有测出可区分于纯融合图的答案质量收益（F1 +0.08 个百分点，95% 区间 -0.39 到 +0.56；EM 差异为 0），却使完整请求平均慢约 1.90 秒（95% 区间 +1.81 到 +2.00 秒）。后台压缩平均 2.69 秒、P95 6.53 秒，1 秒空窗下只有 7/448 次赶在下一轮前完成。** 对这台单 GPU 实验环境而言，该后台方案的开销没有被空窗隐藏。

V2 纯融合图相对无压缩将平均完整延迟从 1.42 秒降到 0.78 秒，但 F1 从 24.11% 降到 20.41%（配对差异 -3.70 个百分点）；相对请求前 LLMLingua-2，它的 F1 低 1.77 个百分点，但平均请求快 3.40 秒。组合方法的 F1 与请求前 LLMLingua-2 差异区间跨过 0，尚未证明两者质量有差别。这里没有一个方法同时胜过无压缩的质量和延迟。

## 验证与边界

- 验证了行数、每会话三轮顺序、跨方法问题一致、当前代码与计划哈希一致、后台无错误、V2/在线预算无超限、完整问题保留。
- 首轮无历史时 V2/组合提示相同 224 / 224，输出相同 224 / 224。
- 所有压缩方法使用共同 50% 原生提示 token 上限；实际长度不同，不能宣称严格等长。
- 相邻问题共 448 对，其中共享提问实体 117 对、共享材料标题 391 对。共享材料可能包含干扰文档，不保证每一对都构成语义上的追问。
- 原始证据仍保留为溯源锚点，压缩记忆是补充；这不是纯压缩图存储实验。
- 旧双路对照保留旧抢答策略，但采用共同来源 ID 修正及预算，与旧 10% 实验的配置不完全相同。
- LLMLingua-2 关闭整段筛选以保留片段来源映射；与过去启用默认整段筛选的基线有差异。
- 最多生成 32 token、确定性解码、单台 GPU、单次测量；长答案截断、GPU 调度与热状态会影响质量和延迟。
- 各方法达到 32 token 输出上限的请求数：{"no_compression": 312, "evidence_graph_dual_path_v1": 402, "llmlingua2": 241, "evidence_graph_fused_v2": 317, "evidence_graph_fused_post_llmlingua2_v2": 317}。
- 服务端缓存 token 的观测最大值为 0，原始提示最长 4676 token。
- 完整延迟从客户端压缩开始到生成结果返回，包含请求开销，排除初始化、评估及后处理；不是首 token 延迟。
- 仅当质量与延迟同时获得支持时才能声称兼顾二者，后台工作移出当前请求不自动等于端到端收益。
